# 保留原文的文字樣式與螢光標記（PRD / 設計）

狀態：第一版已實作（2.1.0）：斜體、粗體、螢光標記。段落裡的彩色字、一個字只有一部分有樣式，列在 TODO。整體架構見 [design.md](design.md)。

實作時跟下面的設計不同的地方：

- **字對到樣式靠位置（像素），不靠位置編號**：每段多一份 `styleBoxes`（斜體、粗體文字串在頁面上的範圍，由字形的 x 位置算出），OCR 讀到的每個字，中心點落在哪個範圍就有那個樣式（§3.2）。螢光標記也一樣，用閱讀器那些 DOM 元素在頁面上的範圍。
- **原文在翻譯時才組**：畫面紀錄存的是每個字（文字、位置、斜體／粗體），不是組好的原文；送給 Claude 前才加上當下的螢光標記，所以標記改變時不用重做 OCR。
- 預讀的下一頁還沒顯示，不知道它的螢光標記，先照沒有標記翻；翻過去後如果有標記，只重翻那幾段。

## 1. 目標

現在每段譯文只用一種字色、標題用粗體，段落裡個別字詞的樣式都沒有保留：原文用斜體標出的書名、外文、強調，有顏色的字（連結、彩色標題），翻譯後都變成一般的字。譯文方框也蓋住了使用者在 Kindle 畫的螢光標記。

這個功能讓譯文保留：

1. **斜體**：中文改用楷體呈現（中文字型多半沒有斜體，硬斜不好看）。
2. **粗體**：段落裡的粗體字。
3. **螢光標記**：使用者畫的標記，在譯文上對應的字也標出來，顏色取閱讀器實際畫的顏色。

段落裡的彩色字（例如藍色的連結）之後再做，見 TODO；做的時候全部保留，不設門檻。

### 1.1 不做的事

- 看圖模式（方式 3）不支援：那條路徑沒有頁面資料，不知道哪些字有樣式。
- 不保留字級變化（段落裡的上標、小字）和底線以外的裝飾。
- 不讓使用者在譯文上畫新的標記：要畫標記時照舊切回原文（README 已經寫了這個做法）。
- 連結只保留顏色，譯文上的字不能點。

## 2. 實測（2026-10-28）

### 2.1 樣式在頁面資料裡的樣子

在《Build a Reasoning Model (From Scratch)》（B0G9527JDW，第一章前後兩批頁面資料，604 行）看到的：

- **樣式記在文字串上**：每個文字串有 `fontStyle`（`normal`／`italic`）、`fontWeight`、`textColor`、`fontKey`。斜體用的是另一套字型（`bookerlyNormItunknown`、`bookerlyBoldItunknown`），`glyphs.json` 裡也標了 `fontStyle: "italic"`。
- **一行可以有好幾個文字串**：樣式改變的地方就切開，例如一行裡的斜體字是自己一個文字串。同一行的文字串共用同一個 `transform`（行首），各字的 `xPosition` 從行首算起。樣式完全相同也可能被切開（照書原始檔的標籤）。604 行裡有 50 行混了不同樣式。
- **看到的樣式**：

  | 樣式 | 用在 | 字形數 |
  |---|---|---|
  | 一般，黑 | 內文 | 31,302 |
  | 斜體，黑 | 內文裡的強調、書名 | 510 |
  | 一般，藍（`#0000ff`） | 連結 | 554 |
  | 粗體，黑 | 內文裡的粗體 | 24 |
  | 粗體／粗斜體，深藍 | 標題、小標 | 2,600 左右 |

- **連結**另外有一條底線：所在行的 `textline` 項目帶著 `backDecoration: [{ type: "linkLine", strokeStartPoint, strokeEndPoint, strokeColor }]`。
- 《愛麗絲夢遊仙境》後段和《傲慢與偏見》第七章前後沒有任何斜體或內文裡的彩色字（這兩個 Kindle 版本沒用），只有章節標題有顏色。

### 2.2 螢光標記

在同一本書上加了一個黃色標記：

- **不在書頁圖片裡**：書頁圖片沒有重畫，閱讀器在圖片上疊了 DOM 元素，一個字（或一個空白）一個：`div.kg-client-highlight.kg-yellow-highlight`，class 裡直接寫了位置範圍，例如 `24751/24817`，還有 `kg-decoration`。
- 所以**辨識頁面不受影響**（實測加了標記的頁照常認得出來），而且標記的位置範圍可以直接對到段落和字。
- 顏色在 class 名稱裡（`kg-yellow-highlight`；選單上還有藍、粉紅、橘）。實際的顏色要從元素的計算樣式取。
- 標記存在 Amazon 的帳號裡（閱讀器呼叫 `updateAnnotations`、`getAnnotations`），翻回這一頁時閱讀器會重新畫出來。

## 3. 設計

### 3.1 找出一段裡有樣式的範圍

在 `page-render.js` 的 `pageParagraphs` 裡，每段多一個 `spans`：

```js
spans: [{ start, end, style: "i" | "b" | "c", color? }]   // 位置範圍
```

- 一段的**基本樣式**是大多數字形用的樣式（字型粗細、斜體、顏色，跟現在算 `fg` 一樣）。
- 跟基本樣式不同的文字串就是一個範圍：斜體（基本樣式不是斜體時）→ `i`，粗體（基本樣式不是粗體時）→ `b`。一個文字串可以同時有好幾種，例如粗斜體。（顏色不同 → `c`，之後再做。）
- 相鄰而且樣式相同的範圍合併。
- 標題整段粗體，不會有 `b` 範圍。

**螢光標記**由 content script 從 DOM 讀：`.kg-client-highlight` 的 class 裡的位置範圍，顏色取那些元素的計算背景色（閱讀器實際畫的顏色，深色主題下也一樣）。依位置範圍對到段落，成為 `style: "h"` 的範圍。

### 3.2 對到 OCR 讀出的字

OCR 讀的是文字，樣式記在位置編號上，要把兩邊接起來：

1. `offscreen.js` 除了每一行，也回傳每個字（Tesseract 的 word）的框。
2. 每個字的中心點，找出它落在哪個文字串的框裡（`ocr-layout.js`），再用該文字串的 `xPosition` 找出最接近的字形，就是這個字的位置編號。
3. 一段的原文組合時，連續落在同一種樣式範圍裡的字用標記包起來：

   ```
   This is <i>reasoning</i> in a <c1>practical</c1> sense.
   ```

   顏色依出現順序編號（`c1`、`c2`），對照表留在這一段的資料裡；螢光標記用 `h1`、`h2`（各自的顏色）。

標記以字為單位：一個字只有一部分有樣式時，整個字算有樣式（第一版先不處理字的一部分，見 TODO）。

### 3.3 送給 Claude

- 翻譯的提示詞加一條：原文裡的 `<i>`、`<b>`、`<c1>`、`<h1>` 等標記，要在譯文裡包住意思對應的字；不要新增、刪除或改名標記；標記不能交錯。
- 校對的提示詞加一條：保留初稿的標記，修改譯文時也要搬到對應的字上。
- **檢查**：譯文裡的標記要成對、不交錯、只出現原文有的名稱。不合格就整段拿掉標記，退回純文字（執行紀錄寫一行），不重問。
- 沒有任何樣式的段落照現在的方式送出，提示詞不變，所以大多數段落的費用不受影響。有樣式的段落多出的 token 只有標記本身。

### 3.4 快取

- 段落的鑰匙（`para:<asin>:<revision>:<start>-<end>`）不變，內容的 `source` 和 `text` 帶著標記。
- **螢光標記會變**：使用者隨時會加、刪標記。鑰匙加上這一段的螢光標記範圍（排序後的雜湊），例如 `…:<start>-<end>:h<hash>`；沒有標記的段落鑰匙不變。加了標記的段落會重新翻譯，只有那一段。
- content script 監看 `.kg-client-highlight` 的增減，有變化就送一個新的 `pageShown`（同一頁），背景程式照常處理：快取裡有就畫，沒有就翻那一段。
- 舊的快取（沒有標記）照樣可用，沒有樣式資料的段落等於沒有樣式。

### 3.5 畫出來

`content.js` 的覆蓋層從純文字改成能畫部分樣式：

- 把譯文解析成文字片段和樣式，**用 DOM 節點建立**（`span`、`textContent`），絕不把模型輸出當成 HTML 塞進頁面。
- `i` → 楷體：`font-family: "BiauKai", "Kaiti TC", "STKaiti", "KaiTi", "Noto Serif TC", serif`（macOS 有「標楷體」、「楷體-繁」；沒有楷體的電腦退回襯線體）。
- `b` → `font-weight: 700`。
- `c1`… → 該段對照表裡的顏色。
- `h1`… → 背景色用標記的顏色。
- 一段譯文分到兩欄時（`splitText`），標記跨過切點的要在兩邊各自關閉、重開。
- `fitText` 量的是整個方框，片段不影響字級計算。

## 5. 驗收條件

1. 原文斜體的字，譯文裡對應的字用楷體；粗體、彩色字照原本的樣子。
2. 加了螢光標記的句子，譯文裡對應的字有同樣顏色的底色；加、刪標記後，這一頁的譯文跟著更新，只重新翻譯那一段。
3. 沒有樣式的段落，送出的內容和費用跟現在一樣。
4. 模型弄亂標記時，這一段顯示純文字，不出錯、不重問。
5. 一段分到兩欄時，樣式在兩邊都對。
6. 模型輸出不會被當成 HTML 執行。

## 6. 已決定（2026-10-28）

- **螢光標記的顏色**：取閱讀器實際畫的顏色（DOM 的計算背景色），不用固定的一組。
- **段落裡的彩色字**：全部保留，不設門檻；但之後再做，第一版只做斜體、粗體和螢光標記（列在 TODO）。
- **一個字只有一部分有樣式**（例如 *reason*ing）：整個字都算有樣式；第一版先不處理，列在 TODO。
